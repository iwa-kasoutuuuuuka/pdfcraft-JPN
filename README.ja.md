# PdfCraft 日本語版 (pdfcraft-JPN)

[PdfCraft](https://github.com/storytold/pdfcraft)(Rust 製のオープンソース PDF リーダー/エディター)を、日本語で使いやすくしたフォークです。英語の README は [README.md](README.md) を参照してください。

- 画面はすべて日本語(未翻訳 0 件)
- 日本語を PDF に**書き込める**(横書き・**縦書き**・**ルビ**・**縦中横**)
- **右綴じ**の見開き表示
- **和暦**の日付
- 日本語 OCR(**Windows 標準 OCR** / Tesseract、縦書き対応)
- **電子印鑑**(名前印・データ印、和暦対応)
- **原稿用紙・便箋**の縦書き文書を本文から作成
- **表記ゆれを無視した検索**(全角/半角・ひらがな/カタカナ・旧字体)
- **個人情報の自動検出と墨消し**(マイナンバー・電話番号・郵便番号・メール)
- OCR 結果の **Word / テキスト書き出し**、**フォルダー一括 OCR**
- **ダークモード**(Ctrl+Shift+D で切り替え)
- **Claude Code・Antigravity** などの AI エージェントから操作(MCP)

> [!TIP]
> **ダウンロード(Windows x64・インストール不要)**
> **[pdfcraft-JPN-windows-x64-portable.zip](https://github.com/iwa-kasoutuuuuuka/pdfcraft-JPN/releases/latest/download/pdfcraft-JPN-windows-x64-portable.zip)**(約 120 MB、OCR モデル込み)

>

> 3. 「Windows によって PC が保護されました」と出たら、「詳細情報」→「実行」。このビルドはコード署名していないため表示されます。
>
> 設定やログは `pdfcraft.exe` の隣の `PdfCraftData` フォルダに保存されます(ポータブル版。詳しくは同梱の `portable.txt`)。AI エージェントから使うときは、同じフォルダの `pdfcraft-cli.exe` を使います([14 章](#14-ai-エージェント連携claude-code--antigravity))。

## 1. ビルドとインストール

必要なもの: [Rust](https://rustup.rs/)(stable)と Git。

```sh
git clone https://github.com/iwa-kasoutuuuuuka/pdfcraft-JPN.git
cd pdfcraft-JPN

# 日本語フォント(BIZ UDPゴシック・BIZ UD明朝・しっぽり明朝, OFL)。
# ./craft-fonts に置くと自動で組み込まれます(CI と同じコミット)。
git clone https://github.com/storytold/craft-fonts.git craft-fonts
git -C craft-fonts checkout b076417b5880bd4154bd22f00695b1d28c6bea83

cargo build --release -p pdfcraft -p pdfcraft-cli
```

できあがるもの:

| ファイル | 役割 |
| --- | --- |
| `target/release/pdfcraft`(Windows は `.exe`) | デスクトップアプリ |
| `target/release/pdfcraft-cli` | コマンドライン / MCP サーバー |

- `craft-fonts` が無くてもビルドはできますが、日本語の**書き込み**ができません(表示はできます)。
- 翻訳は `i18n/` に同梱しているので、追加の設定は不要です。OS の言語が判定できない場合も日本語で起動します。

## 2. 日本語・縦書きで書き込む

次の場所で日本語が使えます。字形は PDF に埋め込まれるので、どのパソコンでも同じように表示され、コピー・検索もできます。

- **テキストを追加**(ページに直接書き込む文字)
- テキストボックスのコメント、Fill & Sign の文字
- ヘッダー/フッター、透かし

横書きは自動で折り返し、「、」「。」「」」などが行頭に来ないよう**禁則処理**をします。

### 縦書きにする

1. 編集 ▸ **テキストを追加** で文字を入力します。
2. 右の書式パネルで **縦書き** ボタン(列のアイコン)を押します。

- 1 列目は枠の右端に置かれ、2 列目以降は左へ並びます。
- 枠の高さが 1 列の長さになります。
- 句読点や括弧は縦書き用の字形に変わり、英単語は横に倒して描かれます。
- 入力中も縦書きのまま表示されます。カーソルは列の中の横棒で、**↑↓** で前後の文字、**←** で次の列(左)、**→** で前の列(右)、**Home / End** で列の先頭/末尾に移動します。Shift を押しながらで範囲選択、クリックやドラッグでもその位置に置けます。IME の変換候補はカーソルの近くに出ます。
- 先に縦書きボタンを押してからページをクリックすると、クリックした位置から 1 列目が始まります(列の長さは 200 pt)。

## 3. ルビ・縦中横

### ルビ(ふりがな)

青空文庫と同じ書き方で、ふりがなを付けられます。横書きでは文字の上に、縦書きでは右側に表示されます。

| 入力 | 意味 |
| --- | --- |
| `東京《とうきょう》` | 直前の漢字の並び(東京)にルビ |
| `｜親文字《るび》` | `｜`(または `|`)から `《` までにルビ |

コピー・検索では、ルビを除いた本文(親文字)だけが取り出されます。

### 縦中横

縦書きの中で、**1〜2 桁の数字**と `!!` `!?` `?!` は自動で正立し、横に並べて 1 文字分に収まります(例: 「令和7年12月」の 7 と 12)。3 桁以上の数字は横倒しのままです。

## 4. 右綴じ(右から左への見開き)

- 右綴じの PDF(`/ViewerPreferences /Direction /R2L`)を開くと、見開き表示でページが**右から左**に並びます。
- **←** キーで次のページへ、**→** キーで前のページへ進みます(本と同じ向き)。
- **ページを整理**画面のサムネイルも右から並び、ドラッグでの並べ替えも右綴じの向きになります。
- 手動で切り替えるには **表示 ▸ ページ表示 ▸ 右から左へのページ順**。
- PDF 自体の設定を変えるには **文書のプロパティ ▸ とじ方向 ▸ 右端**。

## 5. 和暦の日付

| 使う場所 | 書き方 | 例 |
| --- | --- | --- |
| 環境設定 ▸ 日付の形式 | `ggEE年m月d日` / `GE.m.d` | 令和7年11月10日 / R7.11.10 |
| ヘッダー/フッター | `<<ggEE年m月d日>>` / `<<GE.m.d>>` | 同上 |

- 元年にも対応しています(令和元年5月1日)。明治以降のすべての元号を扱えます。
- Fill & Sign の日付スタンプにも反映されます。

### 日本式のページ番号

**ヘッダーとフッターを追加** で、**ページ番号を挿入** の左の一覧から選んで挿入します。AI エージェントからは `doc_header_footer` ツールの文字に同じ書き方を入れます。

| 書き方 | 例(105 ページ目、全 120 ページ) |
| --- | --- |
| `<<- 1 ->>` | - 105 - |
| `<<1 / n>>` | 105 / 120 |
| `<<1ページ>>` | 105ページ |
| `<<第1頁>>` | 第105頁 |
| `<<一>>` | 百五(漢数字。十、十一、二十、百、千、二千二十六 のように書きます) |
| `<<第一頁>>` | 第百五頁 |

- かなや漢字を使う形式には日本語フォントが要ります。日本語フォントの入っていないビルドでは、その理由を示して止まります。

### 和暦/西暦の一括変換

**編集 ▸ 和暦/西暦の一括変換** を開くと、文書の中の日付が一覧になります。変換先(和暦か西暦)を選び、変換したい日付にチェックを入れて **変換** を押します。まとめて 1 回の「元に戻す」で戻せます。

| 見つける書き方 | 例 |
| --- | --- |
| 和暦 | 令和6年5月1日 / 令和元年 / 平成31年4月 / R6.5.1 / H31/4/30 |
| 西暦 | 2024年5月1日 / 2024年5月 / 2024/5/1 / 2024-05-01 / 2024.5.1 |

- 変換後は漢字の書き方になります(R6.5.1 → 2024年5月1日、2019/5/1 → 令和元年5月1日)。全角数字は全角のまま変換します。
- 元号の切り替わりは日付まで確かめます。平成31年5月1日、令和元年4月、昭和64年1月8日のような**ありえない日付は「無効」と表示し、変換しません**。1989年1月のように 2 つの元号にまたがるものも変換しません。
- 電話番号(03-1234-5678)や長い数字の並びは日付と見なしません。西暦の年だけ(2024年)や漢数字(令和六年)は対象外です。
- 変換できる場所: ページの文字(行ごと)、注釈(コメント)の文字、テキストフィールドの値。ページの文字は「テキストを編集」と同じ方法で行を書き換えます。書き換えられない行や、書き換えると正しく読み取れなくなる行は**変更せず**、理由を表示します。日付の書式が付いたフィールドは変更しません。
- AI エージェントからは `dates_find_ja`(探すだけ)と `dates_convert_ja`(変換)で使えます。

## 6. 日本語 OCR(スキャン PDF の文字認識)

**スキャンと OCR ▸ このファイル内** を開き、**テキストを認識** を押します。初期設定は「言語: 日本語」「エンジン: 自動」で、Windows ではそのまま Windows OCR が使われます。縦書きだけのページなら、言語に **日本語(縦書き)** を選ぶこともできます(Tesseract 使用時)。

> エンジンを「内蔵」にすると言語の候補が「英語」だけになります(内蔵エンジンは英語専用のため)。日本語を読むときは「自動」か「Windows OCR」を選んでください。

| エンジン | 準備 | 特徴 |
| --- | --- | --- |
| **Windows OCR** | 不要(Windows 10/11 の日本語言語パックに含まれる) | 速い・高精度。縦書きの列も正しい順で読む。縦書きと横書きが混在するページは段落ごとに分けて認識 |
| Tesseract | [Tesseract](https://github.com/UB-Mannheim/tesseract/wiki) と `jpn.traineddata`・`jpn_vert.traineddata`(縦書き用)を tessdata に入れる | Windows 以外でも使える |
| 内蔵 (ocrs) | `cargo xtask models` | 英語のみ |

- 認識結果は**透明なテキスト**としてページに重なり、検索・コピー・選択ができるようになります(見た目は変わりません)。
- 縦書きの行も、上から下へ・右の列から順に読めるように配置されます。
- 認識した日本語の文字間には余計なスペースが入りません。
- Windows OCR は傾きを補正しません。傾いたスキャンは「傾いた文字行をまっすぐにします」にチェックを入れてください。
- 認識できる言語は Windows の言語設定に入っている OCR 用の言語だけです。日本語が無い場合は **設定 ▸ 時刻と言語 ▸ 言語と地域** で日本語を追加します。

## 7. 電子印鑑

**コメント ▸ スタンプを追加** を開くと、いちばん上に **印鑑** の欄があります。

1. **認印**(名前印)か **データ印**(日付印)を選びます。形は丸か四角形を選べます。
2. 名前を入れます(1〜3 文字は 1 列、4〜6 文字は 2 列の縦書き)。データ印は部署名と日付も入れます。日付は「押した日」か指定日で、**和暦**(令和8.11.12)にもできます。
3. プレビューを確かめて **この印鑑を使う** を押し、ページをクリックして押します。

- 印鑑はスタンプ(注釈)として入るので、あとから移動・拡大縮小・削除・元に戻すができます。
- 一度作った印鑑はスタンプの一覧に残り、次からはそのまま選べます。データ印は押した日の日付で描き直されます。
- 色は朱色(初期値)のほか自由に変えられます。
- AI エージェントからは `page_add_seal` ツールで押せます。

### 契印(ページの境目に押す)

印鑑の欄の **契印として押す** を開くと、作った印鑑をページとページの境目にまたがって押せます。各ページには印鑑の半分ずつが入り、ページを並べるとひとつの印鑑になります。

1. 印鑑を作ります(上の手順 1〜2)。
2. **最初のページ** と **最後のページ** を選びます(初期値は全ページ)。範囲内の隣り合うページすべてに押します。
3. 押す高さ(上・中央・下)と、ページの並び(**次のページが右**(横書き)か **次のページが左**(縦書き))を選び、**契印を押す** を押します。

- 半分ずつの印鑑はそれぞれスタンプとして入ります。まとめて 1 回で元に戻せます。
- 2 つの別の文書にまたがる割印はできません。
- AI エージェントからは `page_add_tally_seal` ツールで押せます。

### ビジネス用スタンプ

印鑑の欄の下に **ビジネス用スタンプ** の欄があります。承認・確認済・至急・社外秘・回覧・複製厳禁・済・重要・控 から言葉をクリックし、ページをクリックして押します。

- 枠は **角丸** か **二重枠** を選べます。言葉は 6 文字までなら自由に入力できます。
- **押した日の日付を入れる** にチェックを入れると、言葉の下に日付(和暦にもできます)が入ります。名前を入れると、その下に名前も入ります。
- 色と大きさも変えられます。印鑑と同じく、あとから移動・拡大縮小・削除・元に戻すができます。
- AI エージェントからは `page_add_business_stamp` ツールで押せます。

## 8. 原稿用紙・便箋の縦書き文書を作る

**PDF を作成 ▸ 縦書き文書** で、本文から縦書きの PDF を作ります。テキストファイル(.txt)の読み込みもできます。

| 用紙 | 内容 |
| --- | --- |
| **原稿用紙** | 20×20 の 400 字詰め(中央に柱)。1 マス 1 字、段落の頭は 1 字下げ。「、」「。」「」」などが行頭に来るときは前の行の下にぶら下げ。1〜2 桁の数字は 1 マスに横並び。表題と作者名の欄も付けられます |
| **便箋** | 縦罫線入り。行数と余白を変えられます |
| **罫線なし** | 縦書きの本文だけ |

- 用紙サイズは A4・A5・B4・B5、縦向き/横向き、明朝体/ゴシック体、罫線の色(緑・赤茶)を選べます。
- ルビ(`漢字《かんじ》`)が使えます。
- できた PDF は**右綴じ**の設定付きで、文字はコピー・検索ができます。
- 「1 ページ目をプレビュー」で、作る前に見た目を確かめられます。
- AI エージェントからは `create_vertical_document` ツールで作れます。

### 原稿用紙に換算した文字数

**ファイル ▸ 文字数と単語数** に、日本語の原稿向けの数も出ます。

- **句読点・記号を除く文字数**: 空白・改行に加えて、「、」「。」「」」「！」「…」「★」などの記号を数えません。
- **400字詰め原稿用紙**: 1 行 20 マス・1 枚 20 行の原稿用紙に書いたときの枚数と、最後の 1 枚の行数です。
  - 1 マス 1 字。改行(段落)ごとに新しい行から書きます。ページが変わるときも新しい行からです。
  - 字下げは勝手に足しません。段落の頭が全角スペースのときだけ、そのマスが空きます。半角スペースはマスを使いません。
  - 「、」「。」「」」などが行頭に来るときは、前の行の最後にぶら下げます(マスを使いません)。
  - ちょうど 400 字なら 1 枚、401 字なら 2 枚(最後の 1 枚は 1 行)です。
- AI エージェントからは `text_word_count` ツールの `characters_without_punctuation` と `manuscript` で受け取れます。

## 9. 表記ゆれを無視して検索

検索バー(Ctrl+F)のオプション、または **検索** パネルの **表記ゆれを無視** にチェックを入れると、次の違いを同じ文字として探します。画面が日本語のときは最初からオンです。

- 全角と半角(ＡＢＣ と ABC、１２３ と 123、ｶﾀｶﾅ と カタカナ)
- ひらがなとカタカナ(がっこう と ガッコウ)
- 旧字体と新字体(國 と 国、學 と 学、髙 と 高、﨑 と 崎 など約 230 組)

見つかった部分は、文書に書かれている文字のまま強調表示されます。「テキストを検索して墨消し」でも同じオプションが使えます。

## 10. 個人情報を探して墨消し

**PDF を墨消し ▸ テキストを検索して墨消し** で **個人情報を検索** を選び、探す種類にチェックを入れて **すべてマーク** を押します。

| 種類 | 見つけるもの |
| --- | --- |
| マイナンバー | 12 桁の番号(4-4-4 の区切りも可)。**検査用数字で確かめる**ので、ただの 12 桁の数字は拾いません |
| 電話番号 | 固定電話・携帯(070/080/090)・050・0120/0570/0800。ハイフン・かっこ・区切りなしのどれでも |
| 郵便番号 | 〒123-4567 / 123-4567 |
| メールアドレス | name@example.jp など |
| 住所(簡易判定) | 都道府県+市区町村+番地。初期設定ではオフ |

- 全角数字やいろいろなハイフンで書かれていても見つけます。日付(2024-11-11)は電話番号と見なしません。
- 見つかった箇所には**墨消しの印**が付くだけです。確かめてから **墨消しを適用** を押すと、文字が完全に消えます。
- AI エージェントからは `redact_find_pii` ツールで探せます。

## 11. フォーム入力の自動そろえ

フォームのテキストフィールドに「全角カナで入れてほしい」「電話番号は半角数字で」といった決まりを付けておくと、入力した文字がフィールドから移ったときに自動でそろいます。

**フォームを作成** でフィールドをダブルクリックし、**テキストフィールドのプロパティ** の **形式** タブで **書式カテゴリを選択** に **日本語の入力** を選び、次のどれかを選びます。

| 種類 | 変わるもの | 例 |
| --- | --- | --- |
| 全角カナ | ひらがな・半角カナをカタカナに(濁点・半濁点はまとめます) | ｶﾞｯｺｳ → ガッコウ、やまだ → ヤマダ |
| ひらがな | カタカナ(全角・半角)をひらがなに | ﾀﾛｳ → たろう |
| 半角数字 | 全角の数字・ハイフン(数字の隣の「ー」も)を半角に | ０３－１２３４ー５６７８ → 03-1234-5678 |
| 半角英数 | 全角の英字・数字・記号を半角に | ｔａｒｏ＠ｅｘａｍｐｌｅ．ｊｐ → taro@example.jp |
| 全角 | 半角の英数字・記号・半角カナを全角に | ABC 123 → ＡＢＣ　１２３ |

- 対応する文字がないもの(漢字など)はそのまま残ります。
- この設定は PDF に保存され、開き直しても効きます。フォームの JavaScript を実行するほかの PDF ビューアーでも同じように変換されます(実行しないビューアーでは入力したままになります)。
- AI エージェントからは `form_set_props` の `format` に `{"type": "japanese", "width": "katakana"}`(`hiragana` / `halfwidth_digits` / `halfwidth_alnum` / `fullwidth`)を渡します。`form_fill` で入れた値も同じように変換されます。

## 12. OCR 結果の書き出し・フォルダー一括 OCR

### テキストを書き出す

**スキャンと OCR ▸ テキストを書き出す** で、ページの文字を **Word(.docx)** か **テキスト(.txt)** に書き出します。

- 縦書きのページは右の列から順に書き出します。Word では、縦書きのページを縦書きの設定(自動・常に・しない)で出力できます。
- 「文字のないページを先に認識する」にチェックを入れると、スキャンしたページを先に OCR してから書き出します(開いている文書は変わりません)。
- Word では日本語のフォントと言語(ja-JP)が設定されます。

### 表を CSV に書き出す

**スキャンと OCR ▸ 表を CSV に書き出す** で、ページの中の表を見つけて **CSV** に書き出します。OCR したスキャンのページでも使えます。

- Excel でそのまま開ける形(BOM 付き UTF-8、改行は CRLF)で保存するので、日本語が文字化けしません。カンマや「"」を含むセルも正しく扱います。
- 罫線のある表は罫線でセルを分けます。罫線のない表は、文字と文字の間の空きで列を分けます(日本語は単語の間に空白がないので、空白では分けません)。
- 「表ごとに CSV を分ける」(`名前_p1_t1.csv` のように保存)か「すべての表を 1 つの CSV にまとめる」(表の間は空行)を選べます。
- 「文字のないページを先に認識する」も使えます(開いている文書は変わりません)。
- 横書きの表だけに対応します。セルを結合した見出しや、罫線のない複雑な表は、列がずれることがあります。

### フォルダーを一括 OCR

**スキャンと OCR ▸ フォルダーを一括 OCR** で、フォルダー内の PDF をまとめて検索できる PDF にします。

- 保存先は「元のファイルと同じ場所に `_ocr` を付けて」か「別のフォルダー」を選べます。元のファイルは上書きしません。
- すでに文字のあるファイル・パスワード付きのファイルは飛ばし、壊れたファイルは失敗として報告して残りを続けます。最後に結果の一覧が出ます。
- サブフォルダーも含められます。1 回に最大 1000 ファイルです。
- AI エージェントからは `export_text`・`export_tables_csv`・`ocr_folder` ツールで使えます。

## 14. AI エージェント連携(Claude Code / Antigravity)

`pdfcraft-cli` は MCP サーバーとして動き、AI エージェントから PDF の閲覧・検索・OCR・編集・結合・分割などができます。サーバーは**エージェントが起動したときだけ**動き、ネットワークのポートは開きません。

### 登録(1 コマンド)

```sh
# Claude Code に登録(--root のフォルダの中だけを読み書きできる)
pdfcraft-cli mcp install --target claude-code --root C:\Users\me\Documents\pdf

# Antigravity に登録
pdfcraft-cli mcp install --target antigravity --root C:\Users\me\Documents\pdf

# Claude Desktop / Cursor にも登録できる
pdfcraft-cli mcp install --target claude-desktop --target cursor --root C:\Users\me\Documents\pdf

# 書き込む前に内容だけ確認
pdfcraft-cli mcp install --target antigravity --root C:\Users\me\Documents\pdf --dry-run

# 登録を外す
pdfcraft-cli mcp uninstall --target claude-code
```

主なオプション:

| オプション | 意味 |
| --- | --- |
| `--scope project` | 今のフォルダの `.mcp.json`(Claude Code)や `.cursor/mcp.json` に登録 |
| `--compact` | エージェントに見せるツールを絞って、トークンを節約 |
| `--force` | 既存の別設定を上書き。ドライブ直下やホームフォルダを `--root` にする場合にも必要 |

安全のための挙動:

- 既存の設定ファイルは `<ファイル名>.pdfcraft-bak` にバックアップしてから、`pdfcraft` の項目だけを追加・更新します。
- ドライブ直下やホームフォルダを `--root` にすると、`--force` を付けない限り拒否します。
- Claude Code に登録するときは、Claude Code を一度閉じてから実行してください。登録後は `/mcp` で確認できます。

### スキル / ワークフロー

| エージェント | ファイル | 内容 |
| --- | --- | --- |
| Claude Code | `.claude/skills/pdfcraft/SKILL.md` | PDF を扱う手順、日本語 OCR、縦書きでの書き込み、安全上の注意 |
| Antigravity | `.agent/workflows/pdfcraft.md` | 同上 |

このリポジトリを開けば自動で使われます。他のプロジェクトで使う場合はコピーしてください。詳しくは [docs/agents.ja.md](docs/agents.ja.md) を参照してください。

### エージェントへの頼み方(例)

- 「`契約書.pdf` の 3 ページ目に『令和7年11月10日 承認』と縦書きで書き込んで、別名で保存して」
- 「スキャンした `議事録.pdf` を日本語で OCR して、検索できる PDF にして」
- 「`a.pdf` と `b.pdf` を結合して、2〜4 ページを抜き出して」

## 15. コマンドラインでの使い方

```sh
pdfcraft-cli text 文書.pdf                     # テキストを取り出す(縦書きは列の順)
pdfcraft-cli render 文書.pdf --page 1 --out p1.png
pdfcraft-cli tools                             # 使えるツールと引数(JSON Schema)の一覧
pdfcraft-cli run --script steps.json --root .  # 複数の手順をまとめて実行
```

`steps.json` の例(縦書きでページに書き込む):

```json
[
  {"tool": "doc_create", "args": {"from": "blank", "pages": 1, "width": 420, "height": 595}},
  {"tool": "page_add_text", "args": {"doc": 1, "page": 1, "rect": [40, 40, 380, 300], "size": 18,
    "vertical": true, "text": "令和7年12月、東京《とうきょう》へ行く。"}},
  {"tool": "doc_save", "args": {"doc": 1, "path": "out.pdf"}}
]
```

- `page_add_text` / `content_update` の `vertical` で縦書きを指定します。
- `ocr_recognize` の `engine: "windows"` と `language: "ja"` で日本語 OCR を実行します。

## 16. 配布パッケージと自動更新

### Windows の配布パッケージを作る

[WiX v5](https://wixtoolset.org/)(`dotnet tool install --global wix --version 5.0.2`)を入れてから、PowerShell 7 で次を実行します。フォントのライセンス表記を同梱するため、`CRAFT_FONTS_DIR` を指定します。

```powershell
$env:CRAFT_FONTS_DIR = "$PWD\craft-fonts"
pwsh packaging/windows/package.ps1 -Arch x64
```

`pdfcraft-<version>-windows-x64.msi`(インストーラー)と `…-portable.zip`(展開して使う版)ができます。大きさは元の PdfCraft とほぼ同じです。実測(Windows x64 の release ビルド)では、アプリ本体 `pdfcraft.exe` が 135 MB、CLI `pdfcraft-cli.exe` が 94 MB、2 つを zip にまとめると 103 MB でした。大部分は埋め込みフォント(日本語・各国語で約 44 MB、簡体字中国語で約 13 MB)で、アプリと CLI の両方に入っています。AI エージェントから使うだけなら、CLI だけを配れば足ります。

### 自動更新について

- 更新の確認先は**このフォーク(iwa-kasoutuuuuuka/pdfcraft-JPN)の GitHub Releases** です。元の英語版の更新が案内されることはありません。
- リリースが無いあいだは、更新の通知は出ません。
- Windows の自動インストールは、**コード署名された**ビルド同士でのみ行われます。署名していない自前ビルドでは、通知が出ても自動では入れ替わらず(安全のため)、手動でダウンロードして入れ直します。
- ダウンロードしたファイルは、リリースに記載された SHA-256 と照合されます。

## 17. 困ったとき・既知の制限

| 症状 | 原因と対処 |
| --- | --- |
| 日本語を書き込もうとすると「Japanese text needs a Japanese font」と出る | `craft-fonts` を入れずにビルドしています。[1. ビルド](#1-ビルドとインストール)の手順で `./craft-fonts` を置いてビルドし直してください |
| OCR の「テキストを認識」が押せない | エンジンが「内蔵」になっていて、モデルがありません。エンジンを「自動」か「Windows OCR」にしてください |
| OCR の言語に日本語が出ない | 選んでいるエンジンが日本語に対応していません(内蔵は英語のみ)。Tesseract の場合は `jpn.traineddata` を tessdata に入れてください |
| Claude Code に `pdfcraft` が出てこない | Claude Code を再起動して `/mcp` で確認してください。`--dry-run` で書き込む内容を確認できます |
| 中国語(簡体字)やヒンディー語などが書き込めない | 書き込みに使えるのは日本語フォントにある文字(日本語・英数字・ギリシャ文字・キリル文字・記号の多く)とタイ語・アラビア語・ヘブライ語です |

既知の制限:

- 縦書きの**入力中**は、ルビの記法(`｜親文字《るび》`)が入力したままの文字で表示されます(確定するとルビとして描かれます)。入力中の句読点・括弧・小書きの仮名は画面用の文字を回転・移動して見せているため、確定後の字形と細部が少し違うことがあります。
- ルビが親文字より長い場合は、はみ出して描かれます(自動で詰めません)。
- 縦中横は 1〜2 桁の数字と `!!` `!?` `?!` だけが対象です。
- 縦書きのテキスト(テキストを追加・原稿用紙)は 1 列が 1 つの文字のまとまりとして取り出されます。個人情報の墨消しでは、見つかった箇所を含む**列全体**に印が付きます。
- 印鑑の文字はゴシック体だけです(篆書体などの印章用の書体はありません)。
- フォルダー一括 OCR と Word の縦書き出力は、実際のスキャン文書と Word では確認していません(テストは合成した PDF で行っています)。
- macOS 用のアイコン(.icns)は Windows で作ったもので、macOS 上では確認していません。
